# 1.2 快速上手与工程骨架

## 编写
这一阶段的目标不是“跑得最快”，而是建立“可扩展、可复用、可评估”的工程骨架。  
当你开始多智能体编排、工具调用、记忆与评估时，目录结构会决定你是否能持续演进。

推荐骨架（已在本阶段建立）：
- `agents/`：各类 Agent 定义
- `workflows/`：多智能体编排
- `tools/`：工具封装
- `memory/`：记忆与状态策略
- `prompts/`：可复用提示模板
- `eval/`：评测集与评测脚本
- `apps/`：应用入口与 Runner 组织
- `docs/`：阶段性文档与设计说明

## 讲解
工程骨架能把“单次成功”变成“可复用能力”。
没有骨架时，你会看到：
- agent 定义与工具耦合在入口脚本
- prompt 分散、无法复用
- 评测样例无统一入口

骨架的价值就是把这些内容“收敛到稳定的落点”。

## 小结
- 结构先行，能力后置。
- 目录不是形式问题，而是复用与评估的基础。
- 后续每个能力都会有明确归属。

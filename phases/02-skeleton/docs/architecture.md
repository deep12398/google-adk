# 工程骨架说明

本骨架目的是让多智能体、工具、记忆与评估具备稳定归属。

## 目录职责
- `agents/`：定义角色与职责，保持最小业务逻辑。
- `workflows/`：负责编排，定义顺序、并行或循环结构。
- `tools/`：外部能力封装（检索、API、存储等）。
- `memory/`：短期/长期记忆策略、会话状态。
- `prompts/`：可复用提示模板与片段。
- `eval/`：评测样例、评分脚本、回归配置。
- `apps/`：应用入口与 Runner 组织。

## 设计原则
- 每个目录职责单一。
- 多智能体协作只放在 workflows。
- 工具函数不得直接调用模型。
- 记忆逻辑与工具逻辑分离。
